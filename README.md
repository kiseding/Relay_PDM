# Relay PDM

从业务接单到生产大货，一张图只留一个真身，一棒一棒往下传。

不是 PLM 全家桶，是 **PDM + 交接审批 + 轻量 BOM**。管四件事：

1. **哪一版算数** —— 每次上传都是新版本，旧的永不覆盖；只有被交接单批过的才算正式版
2. **现在在谁手上** —— 八个环节、七道门，每道门都要主管批、对方签
3. **这张图叫什么** —— 设计编号 / 开模编号 / 客户料号，三个名字一次搜到
4. **这产品由什么组成** —— 三层 BOM，自制件没挂图会亮黄灯

---

## 一、启动

需要 Python 3.10+（本机是 3.13）。第一次先装依赖：

```bash
pip install -r requirements.txt
```

然后：

```bash
python run.py            # http://127.0.0.1:8000   只有本机能开
python run.py --lan      # http://192.168.x.x:8000  同局域网的同事也能开
python run.py --port 9000 --no-reload
```

第一次启动会自动建库、灌一份演示数据（五条需求，铺在第 1/3/4/6/8 环；其中一张交接单正等着审批，另一张卡在模具部 14 天，专门用来看「卡住」长什么样）。

**想推倒重来**：设置页最下面「清空并重置演示数据」，输 `RESET` 即可。

## 二·二、谁能改什么（操作失误的兜底）

录错是常态，所以凡能录进来的都能改。但不能人人能改，规则集中在 `app/db.py` 的 `EDIT_RULES`，
页面只按 `can()` 决定按钮显不显示，路由再按同一个函数校验一次（改前端也绕不过去）。

| 改什么 | 谁能改 | 说明 |
|---|---|---|
| 需求基本信息（客户、产品名、需求说明、料号、备注） | 建单人或主管 | 谁接的单谁负责改，别人只能提意见 |
| **交期** | 主管 / 管理员 | 交期一动影响排产和外协，单独收紧一级 |
| 做色要求、色板色号 | 业务 / 设计 / 工程的技术人员 + 主管 | 技术参数，车间和生产线不碰 |
| 需求来源（自主 / 客案） | 主管 / 管理员 | 改来源会连带改齐套清单，属管理判断 |
| 图档属性（别名、开模编号） | 设计 / 工程 + 主管 | 开模编号由工程部统一编 |
| BOM 增删改 | 工程部 + 主管 | 别的部门只能看，页面会标「只读」 |
| 打样单状态 | 工程 / 业务 / 设计 + 主管 | |
| 客户资料附件 | 建单人 / 主管 | 客户原始图档的进出要有人负责 |
| 结案 / 重新打开 | 主管 / 管理员 | 误结案能一键恢复 |
| 账号（姓名、部门、角色、重置密码） | 仅管理员 | 内置 `admin` 不许降级，防止把自己锁在外面 |

几条实现上的约定：

- **改了就留痕**：每次修改写一条操作记录，记「改前 → 改后」（如 `交期: 2026-12-20 → 2027-01-10`），审计页能查
- **空的输入不覆盖已有值**：补录表单只改填了的那几项
- **勾错能撤回**：齐套项的勾选支持显式取消（`unset` 参数置 0），不是只能加不能减
- **越权不是 403 了事**：被挡回时带一句人话，比如「交期变更需主管或管理员操作」

## 二·五、总看板（admin / boss 专属）

左侧导航第二项「总看板」，只有 `admin` 和 `boss` 看得到，别人点链接会被挡回工作台。

- **八列 = 八个环节**，每张卡片是一条需求，停在哪儿就是卡在哪个部门
- 卡片右上角是**在这一环待了几天**：超过 7 天发黄、14 天发红 —— 这是这套系统最该被盯的数字
- 卡片上的小标签：`待提交` / `待审批` / `待签收` / `被驳回` / `量产中`，以及 `缺件 N`（本环齐套没补齐）
- 顶部统计多了 **齐套未完成**：多少张单卡在「本环节必交项还没交」，不用等群里喊
- 底部两个面板：**堵得最久的五张单**（谁在拖，卡在哪一关）、**客户还没点头的图**（发了但业务没打确认勾）
- 屏幕窄于 1500px 时八列可以左右滑

## 三、八个环节

```
01 接单        业务部        客户需求、做色要求、交期
02 外观设计     设计部·外观    效果图、CMF、色号确认
03 结构设计     设计部·结构    3D 建模、分模、2D 出图、缩水评估
04 开模准备     工程部        开模信息表、开模图、装配图、配镜干涉
05 开模        模具部        报价、采购下单、T0 试模、试样确认
06 后工艺·组装  后工艺部      喷油/电镀/移印、组装、首件确认
07 工程图发布   工程部        正式工程图、BOM 定版
08 量产        生产部        按图生产大货
```

每一环只有一个动作：**提交交接单 → 主管审批 → 对方签收**。签收了，需求才往前走一格。
驳回不删记录，重提算第 2 轮，第 1 轮的过程留着。

### 需求分两类：自主 / 客案

新建需求时先选来源，它决定齐套清单查什么：

| 来源 | 含义 | 清单差异 |
|---|---|---|
| **自主** | 我司自主立项，外观与结构由我司主导 | 第 1 环多查需求说明与做色；第 2 环必须「客户确认外观」 |
| **客案** | 客户来图 / 来样，依客户既定方案转换落地 | 第 1 环多查「客案原始资料已收齐留档」；第 2 环不查客户确认外观（方案本来就是客户的） |

订单列表顶部可按来源过滤并显示条数；看板卡片和详情页头部都有来源标签。
录错来源时，主管或管理员在详情页右上角的下拉里直接改，改一次记一条审计日志。

### 每道门都有尺子：齐套检查

提交交接单前，系统会按环节检查必交项，缺一项就拦下，并告诉你缺哪几项：

| 环 | 转出前必须有 |
|---|---|
| 01 接单 | 客户需求说明、做色/表面处理要求、客户交期（客案另需原始资料已收） |
| 02 外观设计 | 外观效果图、色板/色号已定、客户确认（渠道 + 日期）（客案免查确认） |
| 03 结构设计 | 结构 3D 图、2D 图纸、缩水与变形已评估 |
| 04 开模准备 | 开模信息表、开模图、装配图、开模编号已编、配镜/组装干涉已查 |
| 05 开模 | 模具采购单号、下单日期、T0 试模已完成、试模样已确认 |
| 06 后工艺·组装 | 后工艺方式已定、后工艺首件已确认、组装样品已确认 |
| 07 工程图发布 | 正式工程图 |

能当场填的（做色要求、客户确认、采购单号与下单日、开模编号、T0）在需求页直接补；
图档类缺口提示去「图档」页按类型新建。清单里每一项都写了「为什么要这一项」，
理由取自车间实际返工的原因，不是系统找麻烦。

**为什么卡这么严**：这些项全部来自微信群里的真实返工——缺做色要求把 RP 打成实色、
没开模信息表就报价、图没更新就通知开模、采购单没下就按口头交期排产、没有装配图反复追问、
包胶件飞边、镜片沟槽积油导致装片过紧、铰链封胶位不够灌胶。
详见 `docs/流程诊断与调整.md`。

**塑胶行业的几条专属门槛**（眼镜、手办类）：

- **色号/色板**：颜色只用文字写「哑光黑」迟早扯皮，第 2 环必须落一个 PANTONE 色号或客户色板编号
- **缩水与变形评估**：眼镜细长件、手办薄壁件不改缩水率，出来就是翘的，第 3 环必查
- **配镜 / 组装干涉**：镜片沟槽积油、铰链封胶位不足这类配合问题，第 4 环出图前就得查
- **后工艺首件确认**：批量喷油前不对首件，整批颜色跑偏就是整批报废
- **组装样品确认**：眼镜组装后才知道铰链顺不顺，手办拼缝大不大

## 三·五、打样单（RP / 手样）

打样是贯在 03~06 环之间、可重复多次的支线，**不占主流程的进度**，所以单独一张单。

- 必须选**依据版本**，已作废的版本选不到
- **做色要求必填** —— 缺它打出来的样大概率重做，所以系统直接不放行
- 单号沿用车间习惯的 `RP-090xxx` 流水，接着现有的号往下排
- 状态：待安排 → 制作中 → 已交付，交付时记时间与交付人
- 需求详情页能看到这条需求所有打样记录，接口人也写在单上（手样 陈文建 / 精雕 唐志杰）

## 四、五个规矩（写死在代码里，别指望能配）

1. 上传就是新版本，旧版本永远在，只会变「已作废」
2. 一个图档只有**一个**当前版本，且必须是「已发布」
3. 「客户确认」是独立的一票，业务员打勾，还要写清是微信还是邮件
4. 已提交的交接单上的版本**冻结**，BOM 也一起冻结成快照
5. 只有本部门能推自己那一环，点别人的环节会提示「这一步归 XX 部」

## 五、文件在哪

```
plm-lite/
├── run.py                 启动脚本
├── app/
│   ├── db.py              表结构、八环节定义、齐套清单、演示数据
│   ├── main.py            所有路由
│   ├── templates/         16 个页面模板
│   └── static/app.css     全部样式
├── docs/
│   ├── 系统设计说明.html    给老板看的方案文档
│   └── 流程诊断与调整.md    微信群反馈 → 流程改动，逐条对应
└── data/                  ← 运行时生成
    ├── plm.db             SQLite 数据库（单文件）
    ├── files/             上传的图档原件
    └── secret.txt         登录 cookie 的签名密钥
```

**备份**：把 `data/` 整个拷走。
**换机器**：把 `data/` 拷回同样位置，起来就有。
**注意**：`secret.txt` 丢了所有人都得重新登录，不影响数据。

## 六、改什么改哪里

| 想改 | 改哪 |
|---|---|
| 八个环节的名字 / 归属部门 | `app/db.py` 的 `STAGES` |
| 后工艺类型（喷油/电镀/移印…） | `app/db.py` 的 `FINISHING_KINDS` |
| 部门列表 | `app/db.py` 的 `DEPTS` |
| 图档类型、BOM 来源、单位 | `app/db.py` 的 `DOC_TYPES` / `BOM_SOURCES` / `BOM_UNITS` |
| 页面长相 | `app/static/app.css` |
| 某个页面的排版 | `app/templates/xxx.html` |
| **谁能改什么** | `app/db.py` 的 `EDIT_RULES`（改完立即生效，不用重建库） |
| 业务逻辑 | `app/main.py` 里对应的路由 |

改 `app/db.py` 的 `STAGES` 之后要重建库（删 `data/`），或者在设置页重置。

## 七、这版故意不做

- **3D 在线预览**：UG 的 `.prt` 浏览器打不开，所有非原厂系统都一样。只做文件名 + 版本号 + 下载
- **UG 插件**：要在你机器上装 NX Open，三期再说
- **MRP / 采购 / 成本 / 库存**：BOM 只到「有哪些件、几件、哪张图」
- **多级会签、自定义流程**：固定「本部门主管一级审批」。能配的流程，通常也没人配得清
- **手机 App**：网页自适应，够用
